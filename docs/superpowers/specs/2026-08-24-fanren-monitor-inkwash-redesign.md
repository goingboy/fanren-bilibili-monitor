# 凡人修仙传 B站数据监控 · 水墨风全面重构设计

日期：2026-08-24
状态：已批准（用户授权自主决策）

## 1. 目标

1. **UI**：整体改为「宣纸白·淡雅水墨」风格——米白宣纸底、黑墨笔触、朱砂印章点缀、留白构图。
2. **性能**：首屏可用时间显著缩短；图片代理磁盘缓存；统计批量并发拉取并持久化。
3. **数据准确性**：消除硬编码数字；失败响应不再污染缓存；实时人数环形比例改为动态基准。
4. **功能完成度/人性化**：错误态/空态/加载态完整；数据时效标注（"x 分钟前更新"）；百科页可搜索；移动端可用；尊重 prefers-reduced-motion。

## 2. 技术决策

- 保留 Flask + 原生 JS + ECharts，同栈全面重写。不引入前端框架/构建链。
- ECharts 本地化到 `static/vendor/`（摆脱 CDN 依赖）。
- Google Fonts 保留但提供完整本地字体栈回退。
- 移除 flask-cors（同源服务，无跨域需求），依赖收敛为 flask + requests。
- 使用 Jinja 模板继承（base.html）消除两页重复的头部/背景标记。

## 3. 架构

### 后端
```
app.py            # 应用工厂 + 路由注册（薄层）
bilibili_api.py   # API 封装（WBI 签名、season/stat/realtime）
cache_store.py    # 线程安全缓存 + 磁盘持久化（trend + ep_stat）
img_cache.py      # 图片代理磁盘缓存（hash 文件名，LRU 清理）
config.py         # 端口/缓存TTL/采样间隔等常量（env 可覆盖）
```

关键修正：
- 所有 `_cache` 读写加 `threading.Lock`。
- `episode_stat` 失败结果只缓存 60s，成功缓存 10min。
- 批量统计端点用 `ThreadPoolExecutor(max_workers=6)` 并发拉取。
- 新增后台采样线程：每 60s 对最新一集采一次实时人数（驱动趋势图，页面关着也积累数据）。
- `/api/overview` 补充 rating.score 与追番数来源核验（运行时实测 API 字段，取得到的才展示，展示不了的删除硬编码占位）。
- 统一错误响应格式 `{code:-1, message}`；前端据此渲染错误态。

### 前端设计系统（水墨）
```
static/css/tokens.css    # 色板/字体/间距变量
static/css/base.css      # 重置 + 宣纸纹理背景 + 排版
static/css/components.css# 卡片(墨框)/印章/按钮/标签/进度条等
static/css/pages.css     # 页面专属布局
```

色板：纸 `#f5f1e8` / 深 `#efe9db`；墨 `#1a1a18`(主字) `#4a4a45`(次)；淡墨 `#8a8578`；
朱砂 `#b03a2e`（印章/强调/最新集标记）；黛青 `#3d4a5c`（图表辅助）。
图表统一墨色梯度 + 朱砂强调，白底。

### 页面结构
- base.html：头部导航 + 水墨背景装饰层（山影 SVG、墨点 canvas 替代粒子）+ 页脚。
- index.html：英雄区（数据驱动）→ 名句 → 总览卡（含评分，去硬编码追番或实测接入）→ 修仙进度条 → 集数选择 + 实时面板 → 图表区（ECharts dataZoom 取代自绘分页按钮）。
- wiki.html：现有内容保留，重 styling + 顶部搜索过滤全部条目。

## 4. Loop Engineering 验证流程（每轮执行）

1. 启动 Flask（子进程）。
2. `Invoke-WebRequest` 冒烟测各 API（code==0、字段齐全、耗时记录）。
3. Puppeteer 打开页面：截图桌面 1440px + 移动 390px；读取 console 错误；检查关键 DOM 存在。
4. 数据抽查：对比接口数值与 bilibili 网页值是否一致量级。
5. 发现问题当场修复并重验；全绿后 git commit 作为轮次检查点。

## 5. 轮次划分

| 轮 | 内容 | 验收标准 |
|----|------|----------|
| R1 | 后端重构（模块拆分/锁/负缓存修复/图片磁盘缓存/批量并发/后台采样/依赖收敛） | curl 全 API 通过；ep_stat 二次请求 <50ms；img_proxy 二次命中磁盘 |
| R2 | 设计系统 + base.html + 两页骨架换肤 | 两页桌面+移动截图正常，无 console 错误 |
| R3 | 首页功能区块重建（英雄/总览/进度/选集/实时面板，真实数据） | 数值与 API 一致；无硬编码残留；错误态可见 |
| R4 | 图表重建（四图 + dataZoom + 懒初始化 + 墨色主题） | 四图渲染正确；dataZoom 可用；离屏图不初始化 |
| R5 | 百科换肤 + 搜索过滤 | 过滤即时生效；样式与首页一致 |
| R6 | 性能与体验收尾（字体回退/reduced-motion/骨架屏/时效标注/a11y） | Lighthouse 式人工检查项通过；移动端无横向滚动 |
| R7 | 终验：全新启动端到端回归（两页 × 两视口 × API 抽查） | 全部检查点绿灯 |

## 6. 明确不做（YAGNI）

- 不引入数据库（JSON 文件足够）。
- 不做多番剧管理（单番剧定位）。
- 不做用户系统/登录。
- 不引入打包器、TypeScript、CSS 预处理器。
